Re-targeted 2026-09-17 (R10). The reviewed plan moved every Gangland menu onto Oriel — the original ask was "The inventory-api needs to be basically linked to oriel, thus using oriel features rather than being independent." It now moves onto a new Keystone module. Your WS2-D1 note already asked for no hard Oriel coupling and an api layer; this goes one further: no Oriel dependency at all. Oriel's 0.8.0 G0 (Keystone 1.9.2 bump, forConsumer) is done pending review — the bump stays useful for Oriel's own rebase, forConsumer is no longer a Gangland need. The Keystone half is planned as Phase E6 in docs/extraction-roadmap.md (branch docs-inventory-roadmap, cut from phase-h10-hologram-shop); this section is the Gangland half. The new plan has not had its review pass yet.

What Keystone ships (E6, 1.11.0)

The basic mechanism both plugins duplicate today, sourced from Oriel's menu-core/chest with Gangland's unique pieces folded in: holder-identified menus (MenuHolder, the MenuTarget seam), one MenuListener for click/drag/close/quit that the consumer registers (the keystone-hologram precedent — Keystone still registers nothing itself), ClickKind resolution and SlotHandlers, Menu/Component/SlotView/RenderContext/CloseReason, a trimmed ChestMenu + ChestMenuBuilder, item/fill/border/line components, a per-consumer InventoryService (open-menu tracker + name registry, BeanLifecycle, no static state), MenuFlow/Panel/FlowState reconciled with MultiPanelInventory (in-place switch, suspend/resume), and PageConfig + PagedRegion. Not shipped: animation, requirements, argument bindings, the provider/filter/sort/search registries, deposit slots, the non-chest menu types, YAML loaders, the editor — those stay Oriel's product. Both stacks were audited Spigot-1.16.5-clean.

Scope in Gangland

keystone-inventory enters the poms that used inventory-api at provided scope; plugin.yml keeps depend: [Keystone] only. The domain's dependency on the menu framework is severed as before: User's Set<InventoryHandler> and InventoryRegistry are replaced by the service's tracker — the InventoryHolder identity deletes the linear findByInventory scan, PlayerInventoryCleanup, the static SPECIAL_INVENTORIES map and the non-atomic MultiInventory.ID. The nine core YAML menus are not rewritten: InventoryParser and the handler.* action dialect stay in gangland-impl and target ChestMenuBuilder, so the files under plugins/Gangland_Warfare/ load unchanged. Conditions, filters/search/sort (the 11 files), unique items, villager trades and the AnvilGUI prompt stay Gangland-side as they are. Six consumers (shop-api, lootchest-api, npc-shops, turf, cops-n-crooks, gadget) use only InventoryHandler + Fill + InventoryUtil + flow.* and move mechanically to ChestMenuBuilder, the four components and MenuFlow. The trader barter and sell views keep today's interactive-slot behaviour (SlotView.interactive is Gangland's draggable), so they are re-points, not the deposit-slot redesigns the Oriel plan needed.
