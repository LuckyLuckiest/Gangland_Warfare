## Summary

Before this commit nothing called the planner, the chase arcs or the learner. Now:

- **EvasionClock** (PLAN.md section 5 rows `:42-51` to `:166-176`)
  - `Track` gains `needMs`, `steps`, `narrow`, `seenSince`, `insideMs`, `outsideMs` and `teleported`.
  - The constructor takes `HeatLedger`, `ChaseArcs` and `ChaseLearner` (10 arguments).
  - A new SEEN track stamps `seenSince` and calls `arcs.seen(id)`. That includes the `track == null` path after `clear` dropped the track while the squad was RETURNING.
  - At the switch to SEARCHING the clock sets `narrow` (only when coming from SEEN), then calls `arcs.lost(id)` and `arcs.searchStarted(id)`.
  - On each tick it reads `levelChanged` before `track.level` is overwritten, adds `dt` to `insideMs` or `outsideMs`, and under AUTO recomputes `needMs` when the level changed.
  - The timer is `need = auto && needMs > 0 ? needMs : Seconds_To_Drop`. The star count is `autoCount(...)` under AUTO and the exact old expression otherwise.
  - `autoCount` builds the views, calls `AutoDropPlanner.plan`, writes the section 5 `log.debug` line, calls `arcs.stashPending` before `stars.drop`, and returns `plan.stars()`.
  - `autoNeed` and `autoCount` sit in a try/catch. On any failure the drop is one star at today's timer, and a warning is logged once per player.
  - `steps++` runs only after a drop with `dropped > 0` that leaves him wanted.
  - `startSearch` computes `needMs` and passes it to `fireCountdown`.
  - New `teleported(Player)`.
  - `speed(...)` is split into `inside(player, track)` and `speed(inside, cfg)`.
- **EvasionListener.onTeleport** runs at MONITOR with ignoreCancelled. It skips the causes ENDER_PEARL, CHORUS_FRUIT and UNKNOWN and a null `to`. Otherwise a jump to another world or of more than 32 blocks (`TELEPORT_BLOCKS` constant) calls `clock.teleported(player)`.
- **EvasionModuleConfig** gains these beans:
  - `chaseArcs()` takes `System::currentTimeMillis`.
  - `chaseLearner(ChaseConfigLoader, RepositoryRegistry)` gets both repositories from `getRepository`.
  - `evasionClock(...)` now takes `HeatLedger`, `ChaseArcs` and `ChaseLearner`. These parameters are also the bean-ordering edges.

## Rulings

- Ruling: after a drop `needMs` is not recomputed in the drop branch. It is recomputed by the `startSearch` that the EVADED state always runs on the next tick, which is what fires the new countdown. Why: the post-drop value would be overwritten one tick later with identical inputs, so computing it twice is dead code. Cost if wrong: none observable. The track is EVADED in between, and EVADED never compares progress to need.
- Ruling: `arcs.seen`, `arcs.lost` and `arcs.searchStarted` run in every drop mode. The plan's "no arc or ledger reads in those modes" is honoured for the reads: `view`, `stashPending`, `HeatLedger` and `ChaseLearner` are never touched outside AUTO, and a test pins it. Why: the arc bookkeeping is a cheap write. It keeps respots and `lastLostAt` right when a reload flips a running chase to AUTO, and the learner ignores it outside AUTO (D3). Cost if wrong: a few map lookups per state switch under ONE_STAR.
- Ruling: a chase with no arc under AUTO (only if `ChaseArcListener` missed the start) behaves as ONE_STAR: one star, today's timer, no stash, no warning. Why: there is no ChaseView to plan from. Cost if wrong: that chase silently plays ONE_STAR.
- Ruling: "logs once" is enforced by a `Set<UUID>` (`autoFailed`, never cleared, bounded by player count) but not asserted. The module has no log-capture precedent, and Keystone's logger is log4j. The test asserts the behaviour (one star, the chase continues, today's timer). Cost if wrong: a regression to log-every-time would not be caught by a test.
- Ruling: the variable the plan calls `raised` is named `levelChanged` and fires on any level change, raise or lower. Why: `Seconds_To_Drop` differs per level either way. Cost if wrong: none, because any level change needs the new level's timer.
- Ruling: `onTeleport` also skips a null `getTo()` (it can be null in 1.16.5 API).
