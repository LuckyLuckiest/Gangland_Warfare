    - `isStarChat` is true unless the supplier answers true.
    - `raise` (main thread) and `restore` (any thread, hops).

      `stars.drop(context, 1, DECAY)` -> stop when not wanted.

    `Settings.isWantedTimerEnabled()`.
  - `DataConfig.wantedStars(WantedSettings)` sits next to `wantedKillTrackers()`.
- Star price inside `drop`: today's rule, moved verbatim from WantedExecutor.java:54-60. Each star costs
  `amount > 0 ? Currency.multiply(amount, multiplier^l) : 0`, where l runs from the level before the drop down to target+1.
  The sum is withdrawn once with `context.withdraw`, after the level change succeeded.
- No caller of Wanted was touched (Task 6), and the money rule was not changed (Task 9).

## Rulings
- Ruling: `raise` at the maximum adds nothing, fires no event and returns 0, but still (re)starts the safety-net clock when
  the player is wanted and the timer is on. A cancelled raise starts no clock, and `stars <= 0` does nothing.
  - Why: C3 says "(re)starts ... same as handleWanted today", and handleWanted restarts the clock on every counted kill even
    at max. The spec says every increment guarantees a decay clock. The brief's test names say "StartsNoClock" only for the
    cancelled case. Pinned in `raise_atMaximum_returnsZero`.
  - Cost if wrong: one condition in `raise` plus that assertion. A maxed-out criminal's decay countdown would no longer reset
    on each new crime.
- Ruling: `drop` with `stars <= 0`, or at level 0, returns 0 without calling `setLevel`: no event, no charge, no message.
  - Why: "returns stars actually dropped". There is nothing to change.
  - Cost if wrong: none observable.
- Ruling: `restore` treats the owner as online when `owner != null && owner.isOnline()`.
  - Why: an offline User has no owner (User.java:62).
  - Cost if wrong: none.
