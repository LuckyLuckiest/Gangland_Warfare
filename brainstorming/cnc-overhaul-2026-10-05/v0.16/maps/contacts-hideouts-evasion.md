## 5. Spec drift (what SPEC-0.16.md states wrongly about today's code)

1. 2.5 "WantedAspect.canExecute" gate: WantedAspect/WantedSign live in **gangland-impl**, which cannot name `EvasionClock` (a module class). Evasion state reaches the core only through the api event `WantedEvasionStateEvent` (core would cache the last state per player by listening) or a NEW api seam; the api 2.3 list (RegionProvider, PlaceNames, WaypointType.HOSPITAL) has none. Line cites off: sign aspects `WantedSign.java:139-144` (not 37-40), `WantedAspect.canExecute` :63-82 (not 62-79).
2. 2.5 "price per star": the sign has ONE flat line-4 price via MoneyAspect (REMOVE amount is line 3). No per-star price exists on the sign. `WantedStars.drop` has a star price from settings, but the sign bypasses it with `Wanted.setLevel`.
3. 2.5 "tag their cause through the wanted seam": `WantedClearContract` only clears to 0 (no remove-N); BribeService has no cooldown or evasion check; `T/detainment/bribe/` has no tests. `WantedCause.BRIBE` is documented as the handcuff bribe; no phone/contact cause. `WantedCause` is gangland-core (additive enum value).
4. 2.5 "inventory/phone.yml and phone_*.yml pages": phone pages are impl YAML with static slots; a module cannot ship a page, so a Contacts slot shows even without cnc unless made conditional (`ConditionalSlotParser`), and the click target must be a command (`/glw wanted` has no contribution path).

6. 2.3/5: `CopManager.java:531` is actually **:580** (`spawnTick` starts :511). `getTierForWantedLevel` is at **:151** (not :118). `spawnNearPlayer` :79 is right. The Predicate filters spawner picks only; the ring fallback `findRingLocation` takes no predicate, so "prefers spots 60 degrees ahead" cannot reach ring spawns without a signature change.
7. 2.3 "heading from the last 2 seconds of positions": no position history exists in CopManager, EvasionClock or the squad. The leash is per cop (`PursuingBehavior:77` -> RETURNING); there is no group-level "leash edge" event or "last officer" notion.
8. 2.3 "seeded with the last-known sighting": `NpcSquad.reportSighting` makes `millisSinceSighting() < Lost_Sight_Seconds`, which `EvasionClock.tick :116` reads as SEEN (resets the countdown; would bump 0.15.2 `respots`). Precedent: `recycles` pairs it with `group.markTipOff` so the clock holds (:110). A hand-off seed must do the same or it cancels the evasion it continues.
9. 2.6 "reports, radios Eyes_On, returns to PURSUING": public `reportSighting` is silent; the CONTACT edge needs `AbstractNpc.pursue` (package-private `reportSightingBy`). Keystone CONTACT_LOST is NOT the clock's 3 s: it needs 3000 ms stale plus a member that looked and failed (`NpcSquad:212-228`); EvasionClock uses `millisSinceSighting() >= Lost_Sight_Seconds`. "Posts exempt from stuck recycling" already holds for any non-PURSUING/COMBAT state (`recycles :631`); `hasLiveCop` counts a post as live.
10. 2.7 "backup requests are skipped": backup is requested only on a casualty (`CopRadio:105`) or regroup (`:161`); skipping needs a gate in `CopGroup.requestBackup :158` AND `grantRegroupBackup :170`, and a decision about a backup already granted (`backupUntil`). The ledger is cleared at WantedEndEvent MONITOR.
12. Section 6 "Hideout speed counts only if you arrive unseen": `speed()` returns 1.0 inside the zone and Outside_Zone_Speed outside; there is no per-track "entered unseen" memory. SEEN returns before speed math, so "unseen" is checkable only at hideout entry or at the SEARCHING transition.
13. Spec says no wand/pickup pattern: a 575-line `LootChestWand` and `ChestCooldownManager` already exist in `gangland-lootchest` (a module, so copy not import). Lootchest is the module `gangland-features/gangland-lootchest`, not `gangland-ui/lootchest-api`.
