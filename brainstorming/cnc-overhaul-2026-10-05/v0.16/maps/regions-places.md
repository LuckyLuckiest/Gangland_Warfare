## 1. Region-like models that exist today

There is exactly ONE region model: the turf. No admin-region class exists anywhere (gangland-core has no region/cuboid file: `gangland-core/.../core/` holds bounty, downed, events, feature, money, permission, user, wanted). No restricted zone, hideout, safehouse or district concept exists (grep clean).

## 3. How gangland-api publishes extension points to modules

Two idioms, both live:
1. **DependencyContainer bean-scan contributions** (module-internal, same JVM, resolved by type): interfaces `command/extension/CommandContribution.java:18` (`String parent(); List<Argument> create(Tree,Argument)`), `data/placeholder/extension/PlaceholderContribution.java:13` (`@Nullable String resolve(OfflinePlayer,String)`, default `resolveSetting(String)` since 2.2), `sign/extension/SignTypeContribution`, `SignViewProvider`, `data/gang/GangItemSourceContribution.java:19`. Collector classes in api: `CommandContributions.from(container)` (`getAllInstances(CommandContribution.class)` CommandContributions.java:24), `PlaceholderContributions.from(container)` :22-25 (lazy, cached once: `GanglandPlaceholder.java:50,67-73`, "modules load once per start"), `GangItemSourceContributions.java:23`; sign collector is impl-side `SignContributions.java:27-28`. A module exports one by declaring a `@Bean` returning the interface (e.g. gang: `GangConfig.java:134` `gangPlaceholderContribution(...)`). Consumer side calls `container.getAllInstances(X.class)`; empty list when no module contributed. Tests: `GangItemSourceContributionsTest`; no dedicated test for the Placeholder/Command collectors in api.
2. **Core holder beans** (R9 pattern): final class in api, always present as a core bean, inert until a module installs a view. `data/gang/GangMembership.java:17` (`install(GangMembershipView)`, `isInstalled()`, volatile view, absent-defaults; test `GangMembershipTest`), `data/economy/BankTiers` (`DataConfig.java:132` `bankTiers()`, cops/npc-shops install). Modules consume the holder by constructor injection without `Depends:` on the installer. This is the pattern that already solves "cops must not depend on turf/gang".
3. **Bukkit ServicesManager** (cross-PLUGIN, not module): `GanglandApi` facade registered in `WiringConfig.java:133-137` `ganglandApi(...)` (`register(GanglandApi.class, api, gangland, Normal)`), PlaceholderAPI-style provider `WiringConfig.java:~118`; `Gangland.onDisable` `getServicesManager().unregisterAll(this)` (Gangland.java:63). Inbound: `GanglandContext.installItemVocabularies()` (`GanglandContext.java:204-224`) folds every `ItemVocabulary` registered on the ServicesManager (Bartizan publishes one) before @PostConstruct. Modules never use ServicesManager for each other except to reach Bartizan.
- `GanglandApi.java` (api): `String VERSION = "2.2"` :33 (javadoc lists 2.1, 2.2 additions :26-31; add a 2.3 bullet); `FULL_PREFIX`, `SHORT_PREFIX`; exactly four accessors `users() gangs() waypoints() bankTiers()` (class javadoc says "Exactly four accessors (final ruling R7)"). Impl `gangland-impl/.../GanglandApiImpl.java` (final, 4-arg ctor `(users,gangs,waypoints,bankTiers)`); tests construct it with exactly 4 args: `GanglandApiImplTest:36,49`, `GanglandApiRegistrationTest:41`. Adding a 5th accessor (e.g. `regions()`) changes the ctor and these 3 call sites (additive for api consumers, breaking for the impl ctor); a ServicesManager-only external-plugin facade is not needed by cops.
- Version mechanics: `GanglandContext.java:107` passes `GanglandApi.VERSION` to the module loader as the host line; Keystone floor rule = same major, module minor <= host minor. `VERSION` is asserted nowhere in tests (only `Host_Api` strings in fixtures: `ModuleCommandsTest:173`, `WiringConfigTest:99`, `EntityDamageListenerTest:183`). Module Host_Api today: cops/civilians/gadget/gang/turf/(others using MovedSetting) = 2.2; healthbars, lootchest, mail = 2.0 (`gangland-features/*/src/main/resources/module.yml:6`). Bumping VERSION to 2.3 does not invalidate any existing jar. A module that uses 2.3 surface must declare `Host_Api: 2.3`, and then refuses to load on a 2.2 host.
- Additive rule (CLAUDE.md "Module API contract"): within a major, api only adds; new module strings/knobs go in the module's OWN YAML, not `Messages`/`Settings`. Api tests live in `gangland-api/src/test/java/...` (CrimeServiceTest, GangMembershipTest, GangItemSourceContributionsTest, WantedEvasionStateEventTest, MovedSettingTest, RadioSidesTest, ...); a new api type gets its test there.
- A holder needs a creator: core holders are `@Bean`s in impl configs (`DataConfig`, `WiringConfig`). A module cannot create a core bean, so a "RegionProviders"/`PlaceNames` holder or collector must be a core bean (or a collector that calls `container.getAllInstances(RegionProvider.class)` like idiom 1, which needs a container reference: `PlaceholderContributions.from(DependencyContainer)`).

## 5. Spec drift (SPEC-0.16.md vs today's code)
1. Spec 1 "gangland-core keeps admin regions" and "Nothing exists. Admin regions live in gangland-core; turfs in gangland-turf" (:353): **no admin region exists anywhere**; gangland-core has none. "Keeps" must read "gets". `gangland-core` is also a dependency of api (re-exported), so a RegionProvider type placed in api needs only `org.bukkit.Location`.
2. "so cops never depend on turf": **cops already hard-depends on turf** (module.yml `Depends: [turf, civilians]`, pom dep, 4 files import turf types: CopsNCrooksModuleConfig:53-54, HeatModuleConfig:12, TurfFriendlyFireListener:19-20, HeatLedger:15-17). Also turf itself `Depends: [civilians, gang]` (CLAUDE.md says only civilians), so cops transitively needs Bartizan AND gang. If the goal is "district names work without turf", that is a NEW decoupling, and the RegionProvider SPI does not remove the existing edge.
3. "RegionProvider SPI (id, name, 3D cuboid or sphere ...)": today's turf shape is an **X/Z rectangle, Y ignored, ints** (`CuboidRegion.contains` :46-56), persisted without Y; the existing `turf.data.Region` interface is turf-private (has only `contains` + `getWorld`, no name/owner/tags/Y). Turf cannot contribute 3D bounds without inventing Y (e.g. world min/max) or a schema change.
4. "turf contributes owned turfs and their names": turf has unclaimed turfs (`ownerGangId==null`) and non-unique, free-text `displayName`; "owner" is a gang id (`Integer`), not a player/UUID, and the gang name is only reachable through `GangMembership.nameOf(int)` (api holder). "gang safehouses" (spec :117) do not exist (no class/table); "gang waypoints" do (`Waypoint.forGang()`, type GANG, `gangId`), and Waypoint has `radius` that nothing treats as a region.
5. Hospital (spec 2.8, :172): `performRespawn` runs only on the **downed** path and only when `Death.Respawn.Enable: true`, which ships **false** (settings.yml:229, `Settings.java:615`). With the default config, deaths are vanilla (`PlayerRespawnEvent`), no Gangland code picks the respawn point, and `performRespawn` is never reached. A hospital respawn therefore needs either Respawn.Enable true or a new PlayerRespawnEvent hook. Also `performRespawn` is `private`, receives impl `WaypointManager` (ctor :75) and picks by configured NAME (`Teleport.Waypoint`, default "spawn", gated by `Teleport.Enable` true); there is no nearest-by-type query on `WaypointLookupContract` and no "death world" input at that point (player is alive, in the world they were downed in). Waypoint teleport also applies the waypoint's timer/cooldown/shield, and `IllegalTeleportException` fallback is a direct `player.teleport`.
6. Spec :351 "WaypointRepository.java:56 (valueOf by name, so old rows still load)": correct line and file (`database/repositories/waypoint/WaypointRepository.java:56`) but the safety is one-directional: old rows load; a HOSPITAL row crashes the whole waypoint load on any build without the constant (downgrade hazard). Also `WaypointTypeCommand` needs NO change (values()-driven tab complete and error list).
7. Spec :349 "gangland-api already has `Waypoint.WaypointType.GANG`": true (Waypoint.java:85) but it is a stored-type label only; `isSafe()` is dead.
8. Spec 2.3 "Any other module that consumes RegionProvider (turf, gang) bumps its own Host_Api only if it uses it": holds mechanically (floor rule), but turf is the PROVIDER, so it uses the 2.3 type and must declare `Host_Api: 2.3` as soon as it implements the interface; cops too. Loading either on a 2.2 host would then be rejected (`module.host.incompatible`).
9. `GanglandApi` javadoc "Exactly four accessors (R7)": a `regions()`/`places()` accessor would break that ruling; not required for module consumers (they use container beans).

## 6. Seams (facts for planning, no design)
- A new api interface is discoverable by modules only via: (a) `container.getAllInstances(X.class)` collector pattern (CommandContributions/PlaceholderContributions/GangItemSourceContributions), or (b) a core holder bean created in impl. Both exist; cops already consumes holders (`GangMembership`, `BankTiers`) without `Depends:` on the installer.
- Provider side is natural for turf: it already has `@Bean` registration of ~29 beans (`TurfModuleConfig`), `TurfManager.findAt(Location)` (world-indexed), `getAll()`, displayName and owner id; it would need `Host_Api: 2.3`.
- Waypoint seam: `WaypointLookupContract` is the only module-visible waypoint API; `WaypointManager` is the only impl. Adding a nearest-by-type read means a new method on the contract (additive rule: add a `default` method or a new interface to avoid breaking test mocks/implementors; the only implementor is WaypointManager, mocks use Mockito so unaffected).
- Persistence seams: waypoint `type` is a free String column (no migration for HOSPITAL); turf table has no Y/tag columns; cops owns its own tables/repositories via `RepositoryRegistry.scanAndRegisterRepositories(modulePackage, moduleClassLoader)` (stations/regions registries would add module tables, e.g. next to cops `database` package).
- Query-by-location in 0.16 registries: `TurfManager.findAt` is O(turfs in world) linear; fine at current counts, no spatial index exists.
- Tag vocabulary required by other cards: `restricted`, `hideout` (spec :195); no existing enum/constant for tags anywhere.
- Place-name text slots: cop radio YAML (`Dispatch_Wanted`, `Escalate`) takes `%placeholder%` args supplied in `CopRadio.dispatch`; there is no place argument yet.
- Death-bill code stays in `PlayerDeathListener` (impl); HOSPITAL selection lives in `CustomPlayerDeathListener` (impl); neither can name cops/turf types, so a hospital lookup must go through `WaypointManager`/`WaypointLookupContract` (core) only.
- Test pins that a 2.3 bump touches: none assert `VERSION`; `GanglandApiImplTest`/`GanglandApiRegistrationTest` only break if the `GanglandApiImpl` ctor changes; `CuboidRegionTest`/`TurfManagerTest` pin the Y-ignored/first-match semantics that a provider adapter would rely on.
