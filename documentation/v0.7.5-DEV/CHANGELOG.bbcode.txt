[SIZE=7][B]🚨 Case Closed — v0.7.5-DEV Changelog[/B][/SIZE]

[QUOTE]Traders open their doors, Bankers start taking deposits, and the cuffs finally come off — for a price. Welcome to [B]Part 3 of Cops N Crooks[/B], the release that closes out the module.[/QUOTE]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[SIZE=6][B]Overview[/B][/SIZE]

Three systems land and [B]Cops N Crooks ships as feature-complete[/B]. A stationary [B]Trader NPC[/B] brings a full buy / barter / sell / tip economy to the street, built on a new shared [B]shop-api[/B] framework. A [B]Banker NPC[/B] takes deposits, issues withdrawals, and gates a tier ladder that controls your max balance, daily cap, interest, and weekly / monthly loans. And [B]bail[/B] finally closes the arrest loop — handcuff → jail → pay-your-way-out (or serve your time and walk).

Alongside those, the release ships a real YAML validation layer, a debug logging block, Vault permissions integration, loot-chest polish, and a wave of command ergonomics (tab-completion fixes, a [ICODE]/gangland[/ICODE] alias, optional player targets on [ICODE]bank[/ICODE] commands). One feature shipped and was rolled back inside the cycle — see the Ambiguous list.

[SIZE=6][B]✨ Features[/B][/SIZE]

[SIZE=5][B]Trader NPCs[/B][/SIZE]

A damageable, stationary Citizens NPC that runs a full shop. Placed via an admin command, bound to a [B]shop key[/B] and a [B]trait[/B] from [ICODE]trader_traits.yml[/ICODE]. Right-click opens a buy view; the trader also supports [B]barter[/B] (item-for-item swap, no money involved), [B]sell[/B] (you hand items to the trader for cash), and [B]tip[/B] (spend money to improve the trader's mood toward you).

[LIST]
[*][B]Six built-in traits[/B] — [ICODE]easygoing[/ICODE], [ICODE]hotheaded[/ICODE], [ICODE]stubborn[/ICODE], [ICODE]generous[/ICODE], [ICODE]shrewd[/ICODE], [ICODE]timid[/ICODE] — each with its own mood rates, barter policy, sell-price ratio, and HP. Define your own by adding a new top-level id.
[*][B]Per-player mood[/B] — mood is a [B]positive-only[/B] scalar. Tipping and successful purchases both push mood up; there's no anger / negative track by design. At max mood the trader gives the configured [ICODE]Min_Friend_Discount[/ICODE] on buys.
[*][B]Barter is a pure item swap[/B] — no money ever changes hands on a barter. The trader values incoming items against the category rates set in the shop file and accepts / rejects based on the trait's [ICODE]Barter_Price_Ratio[/ICODE]. Turn it off per-trait with [ICODE]Allows_Barter: false[/ICODE].
[*][B]Sell[/B] — per-category valuation via [ICODE]Sell_Price_Ratio[/ICODE]. Players can liquidate loot they don't want; server owners tune how generous each trait is per category.
[*][B]Item freshness via decorate, not NBT[/B] — newly-delivered shop items are re-decorated on every purchase, so configured lore / display names refresh even if an old YAML shape changed in between.
[*][B]Admin editing in-game[/B] — no YAML wrestling needed day-to-day. [ICODE]/glw trader edit shop <key>[/ICODE] retargets the trader in your crosshair, [ICODE]edit trait <id>[/ICODE] changes the personality, [ICODE]edit name[/ICODE] opens an anvil to rename (spaces supported), [ICODE]remove[/ICODE] deletes the trader you're looking at.
[*][B]Trader is damageable by default[/B] — [ICODE]Invulnerable: false[/ICODE] on the trait makes the NPC killable so you can actually rob a shop. Default traits ship invulnerable; [ICODE]stubborn[/ICODE] is the example "killable" trait.
[*][B]Persistent repository[/B] — traders are saved by the plugin, [B]not by Citizens' [ICODE]saves.yml[/ICODE][/B] ([ICODE]SHOULD_SAVE = false[/ICODE] at spawn). One source of truth.
[/LIST]

[B]New file — [ICODE]trader_traits.yml[/ICODE] shape:[/B]

[CODE=yaml]
easygoing:
   Display_Name: "Easygoing"
   Mood_Per_Tip_Currency: 0.0008   # mood gain per currency unit spent on a tip
   Mood_Per_Purchase: 0.03         # mood gain on a successful buy
   Min_Friend_Discount: 0.92       # price multiplier at mood = +1 (0.92 = 8% off)
   Allows_Barter: true
   Sell_Price_Ratio: 0.55          # fraction of ask the trader pays when BUYING from the player
   Barter_Price_Ratio: 1.0         # barter credit per item (1.0 = parity; defaults to Sell_Price_Ratio)
   Max_Health: 20.0                # half-hearts
   # Invulnerable: false           # (optional) omit for default-invulnerable traits
[/CODE]

[SIZE=5][B]Shop API Framework[/B][/SIZE]

The shop UI, persistence, and transaction logic were extracted into a new [ICODE]gangland-ui/shop-api[/ICODE] module so any future shop surface — not just traders — can reuse them.

[LIST]
[*][B]Per-shop YAML files[/B] under [ICODE]plugins/<plugin>/shop/<key>.yml[/ICODE], scanned on boot and hot-reloaded through the standard [ICODE]/glw reload[/ICODE] pipeline.
[*][B]Typed transaction returns[/B] — [ICODE]PurchaseResult[/ICODE], [ICODE]BarterResult[/ICODE], [ICODE]SellResult[/ICODE] replace the old boolean-plus-enum mess. Each carries a clean reason enum plus the outcome payload (item stack delivered, money debited, etc.).
[*][B]Shop-level messaging contract[/B] — [ICODE]ShopMessageContract[/ICODE] and [ICODE]TraderMessageContract[/ICODE] route every user-facing string back through the [ICODE]Messages[/ICODE] enum, so every shop / trader line is translatable without feature-module imports.
[*][B]Admin GUIs[/B] — shop definitions, buy entries, sell categories, and per-category barter / sell pricing are all editable in-game. Edits round-trip to YAML via [ICODE]ShopYamlWriter[/ICODE] with zero restarts.
[*][B]Shop entries deliver per-copy stacks[/B] — a buy entry's [ICODE]template.amount[/ICODE] is one [I]copy[/I]; the [ICODE]BUY AMOUNT[/ICODE] picker counts copies, not items. Multi-item copies (e.g. a stack of 5 arrows) are supported.
[/LIST]

[B]New admin command:[/B]

[CODE]
/glw shop remove
[/CODE]

[SIZE=5][B]Inventory & UI Refresh[/B][/SIZE]

A new [B]multi-panel inventory[/B] framework underpins every revamped GUI this cycle. Panels swap [B]in place[/B] without closing the underlying Bukkit inventory, so switching between trader categories, banker sections, and shop-admin pages no longer triggers the familiar close-and-reopen flicker.

[LIST]
[*][B]Multi-panel framework[/B] — one Bukkit inventory, many logical panels. Each flow (trader, banker, shop admin) registers its panels once and transitions between them with no [ICODE]closeInventory[/ICODE] call in between.
[*][B]Flow panels for traders and bankers[/B] — the trader buy / barter / sell / tip surfaces and the banker deposit / withdraw / tier surfaces now run as flow panels on top of the framework. Rendering logic was rewritten to coalesce updates into a single repaint per click.
[*][B]Admin legacy inventory migrated[/B] — the legacy admin GUIs were ported onto the multi-panel framework. Panel transitions inside admin flows are now flicker-free, matching the rest of the UI.
[*][B]Shift-click + drag-and-drop in admin editors[/B] — barter and sell category editors accept shift-click moves and drag operations from the player inventory; previously they only accepted single-click placement.
[*][B]Custom inventory filter system[/B] — per-view filter controls (search, category sort, etc.) are now first-class, so heavy lists (gang member browsers, shop catalogues) stay navigable.
[*][B]Gang inventory revamp[/B] — the gang member browser ships with search filters and an updated layout; pagination and rank annotations are easier to scan.
[*][B]New inventory layouts[/B] — several screens were rebuilt from scratch with consistent borders, panel headers, and decorate pipeline coverage. General icon/glass-pane polish across the board.
[*][B]Shop item freshness[/B] — car entries now run through a dedicated car item refresher on every delivery, so an updated [ICODE]cars.yml[/ICODE] shape is reflected in the next handout. Trader-bought ammunition runs through an [ICODE]AmmunitionItemRefresher[/ICODE] so bought stacks merge cleanly with looted ones instead of occupying a separate slot.
[*][B]Item-equality by serialized payload[/B] — shop, barter and sell comparisons now serialize the full item (NBT + meta), not just [ICODE]Material[/ICODE]. Custom-model variants and differently-tagged stacks stay distinct where they used to collide.
[/LIST]

[SIZE=5][B]Banking & Banker NPC[/B][/SIZE]

Every player gets an [B]account balance[/B] (cash in hand) and a [B]bank balance[/B]. 0.7.5 turns the bank from a cash drop into a full ladder with a dedicated NPC.

[LIST]
[*][B]Banker NPC[/B] — a stationary Citizens NPC that opens the bank UI on right-click. Create / delete via a command; identical-looking Banker NPCs can be scattered across your map without each one needing its own config.
[*][B]Tier ladder[/B] — four default tiers ([ICODE]Basic[/ICODE], [ICODE]Premium[/ICODE], [ICODE]Elite[/ICODE], [ICODE]Vault[/ICODE]) gate max balance, daily deposit cap, interest rate, death-loss discount, and weekly / monthly loan drops. Every Banker NPC offers the same ladder — there's no per-NPC pricing.
[*][B]Rolling-window daily cap[/B] — deposits and withdrawals use a rolling window, not midnight, so splitting a transaction across midnight can never count against two separate days.
[*][B]Interest[/B] — accrued continuously as a fraction of bank balance per 24h, clamped at [ICODE]Max_Balance[/ICODE].
[*][B]Weekly / monthly loans[/B] — free currency deposited into the bank on a fixed cadence per tier ([ICODE]Weekly_Loan_Amount[/ICODE], [ICODE]Monthly_Loan_Amount[/ICODE]).
[*][B]Death-loss discount[/B] — tier-scoped fraction subtracted from the death-tax deduction (so higher tiers take a smaller hit on death).
[*][B]Rename fee[/B] — charged from cash every time a player renames their account at a Banker. [ICODE]0[/ICODE] disables it.
[*][B]BigDecimal money handling[/B] — price arithmetic on bank operations now uses [ICODE]BigDecimal[/ICODE], so large balances stop suffering from floating-point drift.
[*][B]Admin reset[/B] — [ICODE]/glw bank resetcap <player|all>[/ICODE] wipes the rolling-window cap for one player or everyone.
[*][B]Optional player targets on every bank command[/B] — [ICODE]/glw bank deposit <amount> [player][/ICODE] / [ICODE]/glw bank withdraw <amount> [player][/ICODE] credit / debit another player's bank as admin actions.
[/LIST]

[B]New file — [ICODE]npc/bank_tiers.yml[/ICODE] shape:[/B]

[CODE=yaml]
Basic:
   Display_Name: "&7Basic Account"
   Max_Balance: 100_000
   Upgrade_Cost: 0                # first tier should be 0
   Order: 0                       # ascending; lower = earlier in the ladder
   Daily_Deposit_Limit: 10_000    # 0 = uncapped
   Interest_Rate: 0.0             # fraction per 24h (0.015 = 1.5%/day)
   Death_Loss_Discount: 0.10      # 0–1; fraction subtracted from death tax
   Weekly_Loan_Amount: 500        # 0 = disabled
   Monthly_Loan_Amount: 2_000

Elite:
   Display_Name: "&6Elite Account"
   Max_Balance: 10_000_000
   Upgrade_Cost: 500_000
   Order: 2
   Daily_Deposit_Limit: 1_000_000
   Interest_Rate: 0.0075
   Death_Loss_Discount: 0.50
   Weekly_Loan_Amount: 10_000
   Monthly_Loan_Amount: 50_000
[/CODE]

[/CODE]

[SIZE=5][B]Bail — Closing the Arrest Loop[/B][/SIZE]

Handcuff → jail now has a paid way out. When a player is jailed, the paperwork view exposes a [B]Pay Bail[/B] action that charges the player's balance, restores their seized inventory, and releases them.

[LIST]
[*][B]Cost scales with wanted level[/B] — [ICODE]Bail.Base_Cost + (wanted_level * Bail.Per_Wanted_Level)[/ICODE]. A one-star arrest pays base; a five-star fugitive pays a lot more.
[*][B]Inventory restoration[/B] — a successful bail routes through the same [ICODE]ReleasePipeline[/ICODE] that a served sentence or admin-release uses, so seized items come back intact.
[*][B]Insufficient-funds path[/B] — [ICODE]BailResult.INSUFFICIENT_FUNDS[/ICODE] is surfaced as a distinct message; no partial charge.
[*][B]Handcuff bribe is separate[/B] — while handcuffed (pre-jail) you can still bribe the arresting cop; that's [ICODE]Handcuff_Bribe[/ICODE], with its own [ICODE]Base_Cost[/ICODE] / [ICODE]Per_Wanted_Level[/ICODE]. Bail is post-jail only.
[*][B]Jail bribe[/B] — a risky shortcut from inside the cell. Pay the cost and roll against [ICODE]Success_Chance[/ICODE]; on failure you eat a [ICODE]Fail_Penalty_Seconds[/ICODE] sentence extension.
[*][B]Sentence[/B] — if you pay nothing, serving [ICODE]Base_Seconds + wanted * Per_Wanted_Level_Seconds[/ICODE] releases you automatically.
[/LIST]

[SIZE=5][B]Loot Chest Polish[/B][/SIZE]

Loot chests got a big quality pass.

[LIST]
[*][B]Item preview[/B] — the chest advertises what it's holding before you open it. No more blind clicks.
[*][B]Floating key / lockpick[/B] — the required unlock item hovers above the chest as a plain item (no more armor-stand placeholder), so the visual lines up with how the game actually renders custom items.
[*][B]Drop chances replace tier requirement[/B] — per-table [ICODE]Rarity_Overrides[/ICODE] and per-item [ICODE]Drop_Chance[/ICODE] buckets ([ICODE]COMMON[/ICODE], [ICODE]UNCOMMON[/ICODE], [ICODE]RARE[/ICODE], [ICODE]EPIC[/ICODE], [ICODE]LEGENDARY[/ICODE]) decide what rolls. Tier gating still controls [I]which table[/I] a chest draws from; it no longer gates individual items inside a table.
[*][B]Natural drops[/B] — weapons rolled from a chest now drop as real weapon items (not placeholder renders).
[*][B]Hologram drop for weapons[/B] — weapon drops float under a hologram showing the weapon's display name.
[*][B]Repair system deleted[/B] — the loot-chest repair path was removed. If you were relying on it, wire it back through the shop-api sell flow or a custom handler.
[*][B]Validation layer[/B] — the chest loader now reports malformed entries with a line number instead of silently skipping them.
[/LIST]

[LIST]

[SIZE=5][B]Commands & Permissions[/B][/SIZE]

[LIST]
[*][B]New [ICODE]/glw permissions[/ICODE] command[/B] — list / inspect / grant / revoke permissions directly in-game. Splits cleanly from the rank command.

[*][B][ICODE]/glw gang members[/ICODE][/B] — list the members of a gang from the command line, with paging and the standard rank annotations. Useful for admin inspection without opening the GUI.
[*][B]Rank schema + Vault-group rank command fix[/B] — the rank command's Vault-group apply path was reading a stale schema, so group changes weren't always propagating to Vault. Rank edits now round-trip cleanly.
[/LIST]

[SIZE=5][B]YAML Validation Layer[/B][/SIZE]

Every loader in the plugin now runs through a shared validator.

[LIST]
[*][B]Unknown-key detection[/B] — a key that isn't in the declared schema gets reported with its line number. Catches dead keys left over from upgrades.
[*][B]Required-key / missing-node reporting[/B] — a missing section still falls back to defaults (same as before) but now logs that the fallback was used, so you can re-add the section on the next edit.
[*][B]Depth tracking[/B] — nested paths like [ICODE]Cops.Behaviour.Cuff_Radius[/ICODE] resolve and validate correctly without custom code in every loader.
[*][B]Fallback message loading from the jar[/B] — if [ICODE]message/*.yml[/ICODE] is missing or corrupt, the loader falls back to the bundled copy inside the jar instead of hard-failing.
[*][B]Missing configuration nodes added[/B] — the defaults that were loaded silently in prior versions are now explicitly documented in the files so [ICODE]/glw reload[/ICODE] reports them accurately.
[/LIST]

[SIZE=5][B]Debug Logging[/B][/SIZE]

Module-level debug logging is now a first-class config surface instead of a JVM-flag dance.

[LIST]
[*][ICODE]Debug.Enabled: true[/ICODE] + [ICODE]Debug.Modules: [<module>, ...][/ICODE] flips log levels at runtime. Restart the server after editing.

[SIZE=5][B]Trader & Bank[/B][/SIZE]

[*][B]Trader invulnerable tag[/B] — the [ICODE]Invulnerable: false[/ICODE] trait wasn't propagating to the Citizens NPC, so "killable" traits weren't actually killable. Fixed by setting both the Citizens protected flag and the Bukkit [ICODE]LivingEntity[/ICODE] invulnerable flag at spawn.
[*][B]Bargain / tip views dropped[/B] — per the trader simplification, bargain and tip-view GUIs were removed and their bug list with them. Tipping is still supported via command / shop integration; the dedicated anvil flow is gone.

[*][B]Ammunition stacking from trader[/B] — bought ammo now runs through [ICODE]AmmunitionItemRefresher[/ICODE] and merges with looted stacks instead of occupying a separate slot.
[*][B]Shop item equality by [ICODE]Material[/ICODE] only[/B] — buy / barter / sell comparisons used to match on [ICODE]Material[/ICODE], so custom-model variants and differently-tagged stacks collided. Comparisons now serialize the full item.
